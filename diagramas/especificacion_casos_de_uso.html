Especificación de Casos de Uso

Sistema de Evaluación de Riesgo Crediticio para Inmobiliaria

CU-01 — Iniciar sesión con 2FA

CU-01Iniciar sesión con 2FA
ActoresPropietario, Administrador, Operador
Dependencias
  • RF-07 Autenticación de usuarios con doble factor.
  • RNF-03 Seguridad de autenticación y control de acceso.
  • RNF-04 Almacenamiento seguro de contraseñas (hash).
PrecondiciónEl usuario está registrado y activo en el sistema.
DescripciónDefine el proceso mediante el cual un usuario se autentica con credenciales y un segundo factor (código TOTP) antes de acceder al sistema, aplicando el control de acceso según su rol.
Secuencia normal
1El usuario ingresa su correo y contraseña y presiona "Ingresar".
2El sistema valida las credenciales contra la base de datos.
3El sistema solicita el código de doble factor (OTP).
4El usuario ingresa el código de su aplicación de autenticación.
5El sistema valida el código y genera el token de sesión.
6El sistema concede el acceso según el rol del usuario y registra el evento en auditoría.
PostcondiciónEl usuario queda autenticado con una sesión activa y el inicio de sesión queda registrado en la auditoría.
Excepciones
2Si las credenciales son incorrectas: el sistema muestra "Credenciales incorrectas", registra el intento fallido y retorna al paso 1.
4Si es el primer inicio de sesión: el sistema muestra el código QR para configurar el 2FA antes de continuar.
5Si el código OTP es incorrecto: el sistema deniega el acceso y solicita reintentar.

CU-02 — Gestionar usuarios

CU-02Gestionar usuarios
ActoresAdministrador, Propietario
Dependencias
  • RF-10 Gestión de usuarios (alta, edición, baja).
  • RF-08 Control de acceso por roles.
  • RNF-03 Control de acceso basado en roles (RBAC).
  • RNF-10 Trazabilidad y auditoría.
PrecondiciónEl usuario ha iniciado sesión con rol administrador o propietario.
DescripciónDefine el proceso mediante el cual un administrador da de alta, edita, activa o desactiva usuarios y les asigna su rol correspondiente.
Secuencia normal
1El administrador accede al módulo de usuarios.
2El sistema lista los usuarios de su empresa.
3El administrador crea un usuario o selecciona uno existente para editar.
4El administrador ingresa/edita los datos y asigna el rol, y presiona "Guardar".
5El sistema valida los datos, guarda los cambios y registra el evento en auditoría.
PostcondiciónEl usuario queda creado, modificado o desactivado, y el cambio queda registrado en la auditoría.
Excepciones
4Si el correo del usuario ya existe: el sistema muestra un mensaje de duplicidad y mantiene los datos para su corrección.
5Si el usuario no tiene permisos: el sistema deniega la acción.

CU-03 — Gestionar clientes

CU-03Gestionar clientes
ActoresOperador, Administrador
Dependencias
  • RF-01 Registro de clientes.
  • RF-02 Gestión de clientes (ver, editar, eliminar).
  • RNF-04 Protección de la información del cliente.
  • RNF-10 Trazabilidad y auditoría.
PrecondiciónEl usuario ha iniciado sesión y está autorizado.
DescripciónDefine el proceso mediante el cual un operador registra, visualiza, edita o da de baja clientes (personas físicas o jurídicas), asegurando la unicidad del documento.
Secuencia normal
1El usuario accede al módulo de clientes.
2El sistema lista los clientes de la empresa.
3El usuario registra un nuevo cliente o selecciona uno existente.
4El usuario ingresa/edita los datos personales y financieros y presiona "Guardar".
5El sistema valida que el documento (DNI/RUC/CE) no esté duplicado.
6El sistema guarda la información y registra el evento en auditoría.
PostcondiciónEl cliente queda registrado, actualizado o dado de baja, y el evento queda registrado en la auditoría.
Excepciones
5Si el documento ya está registrado: el sistema muestra un mensaje de duplicidad y mantiene los datos para su corrección. Retorna al paso 4.

CU-04 — Configurar motor de reglas y criterios

CU-04Configurar motor de reglas y criterios
ActoresAdministrador
Dependencias
  • RF-03 Evaluación de scoring mediante reglas configurables (configuración).
  • RF-12 Evaluación por criterios ponderados.
  • RNF-08 Escalabilidad / configurabilidad.
  • RNF-10 Trazabilidad y auditoría.
PrecondiciónEl usuario ha iniciado sesión con rol administrador.
DescripciónDefine el proceso mediante el cual un administrador configura el motor de reglas IF-THEN (parámetros, operadores, pesos, reglas determinantes y umbrales) y los criterios de evaluación ponderada.
Secuencia normal
1El administrador accede a la configuración del motor de scoring.
2Crea un modelo/motor de reglas o selecciona uno existente.
3Define las reglas con su parámetro, operador, valor de referencia y peso.
4Marca las reglas determinantes cuando corresponda.
5Configura los umbrales de clasificación (bajo, medio, alto).
6El sistema valida y guarda la configuración, y registra el evento en auditoría.
PostcondiciónEl modelo de reglas/criterios queda configurado y disponible para las evaluaciones.
Excepciones
3Si una regla tiene datos inconsistentes: el sistema muestra un error y no la guarda.
5Si los umbrales se solapan o son inválidos: el sistema rechaza la configuración.

CU-05 — Evaluar riesgo de cliente (caso de uso central)

CU-05Evaluar riesgo de cliente
ActoresOperador
Dependencias
  • RF-03 Evaluación de scoring mediante reglas.
  • RF-04 Clasificación de riesgo (bajo/medio/alto/rechazado).
  • RF-05 Verificación contra listas de sanciones (ONU/OFAC).
  • RNF-01 Tiempo de respuesta (≤ 3 s).
  • RNF-10 Trazabilidad y auditoría.
PrecondiciónEl usuario ha iniciado sesión y está autorizado; el cliente está registrado y existe un motor de reglas activo.
DescripciónDefine el proceso mediante el cual un operador ejecuta la evaluación de riesgo de un cliente aplicando el motor de reglas, verificando listas de sanciones y clasificando el resultado.
Secuencia normal
1El operador selecciona un cliente y solicita la evaluación.
2El sistema recopila los datos financieros del cliente.
3El sistema verifica al cliente contra la lista de sanciones (ONU/OFAC).
4El sistema aplica las reglas IF-THEN y calcula el puntaje ponderado.
5El sistema clasifica el riesgo en bajo, medio, alto o rechazado.
6El sistema genera la explicación y recomendación, muestra y almacena el resultado, y lo registra en auditoría.
PostcondiciónLa evaluación queda almacenada con su puntaje y clasificación, y el evento queda registrado en la auditoría.
Excepciones
3Si el cliente coincide con la lista de sanciones: la clasificación se fuerza a alto/rechazado.
4Si se incumple una regla determinante: el resultado es "rechazado" de forma directa.
2Si faltan datos obligatorios del cliente: la evaluación se marca como incompleta.

CU-06 — Generar reportes

CU-06Generar reportes
ActoresOperador, Administrador
Dependencias
  • RF-06 Generación de reportes.
  • RNF-01 Tiempo de respuesta.
  • RNF-04 Acceso a la información según rol.
  • RNF-09 Compatibilidad con navegadores modernos.
PrecondiciónEl usuario ha iniciado sesión y está autorizado; existen evaluaciones registradas.
DescripciónDefine el proceso mediante el cual un usuario consulta y exporta reportes de las evaluaciones realizadas y visualiza estadísticas en un tablero.
Secuencia normal
1El usuario accede al módulo de reportes.
2Aplica filtros (fecha, cliente, clasificación).
3El sistema muestra las evaluaciones y las estadísticas del tablero.
4El usuario solicita la exportación a PDF.
5El sistema genera y descarga el reporte en PDF.
PostcondiciónEl reporte se muestra en pantalla o se descarga en PDF.
Excepciones
3Si no hay resultados para los filtros: el sistema muestra un aviso.
5Si ocurre un error al generar el PDF: el sistema notifica el fallo.

CU-07 — Consultar auditoría / historial

CU-07Consultar auditoría
ActoresAdministrador, Propietario
Dependencias
  • RF-09 Auditoría de operaciones y evaluaciones.
  • RNF-10 Trazabilidad y auditoría.
  • RNF-03 Control de acceso basado en roles.
  • RNF-04 No exposición de secretos en la bitácora.
PrecondiciónEl usuario ha iniciado sesión con rol administrador o propietario.
DescripciónDefine el proceso mediante el cual un administrador o el propietario consulta la bitácora de operaciones y evaluaciones. El administrador ve solo la auditoría de su empresa; el propietario ve la de todas las empresas.
Secuencia normal
1El usuario accede al módulo de auditoría.
2Aplica filtros (fecha, usuario, tipo de evento, módulo, resultado).
3El sistema muestra los registros paginados con usuario, fecha/hora, IP y resultado.
4El usuario revisa el detalle de un registro específico.
PostcondiciónEl usuario visualiza el historial de operaciones filtrado según su alcance de empresa.
Excepciones
3Si no hay registros para los filtros: el sistema muestra un aviso.
3Un administrador solo puede ver la auditoría de su propia empresa; el sistema restringe el resto.

CU-08 — Gestionar empresas

CU-08Gestionar empresas
ActoresPropietario
Dependencias
  • RF-11 Gestión multi-empresa (multi-tenant).
  • RNF-03 Acceso exclusivo del propietario.
  • RNF-04 Aislamiento de datos entre empresas.
  • RNF-08 Escalabilidad.
PrecondiciónEl usuario ha iniciado sesión con rol propietario.
DescripciónDefine el proceso mediante el cual el propietario da de alta, edita o desactiva empresas dentro del sistema multi-tenant, garantizando el aislamiento de sus datos.
Secuencia normal
1El propietario accede al módulo de empresas.
2El sistema lista las empresas registradas.
3El propietario crea una empresa o selecciona una existente.
4Ingresa/edita los datos de la empresa y presiona "Guardar".
5El sistema valida y guarda los cambios, y registra el evento en auditoría.
PostcondiciónLa empresa queda creada, modificada o desactivada, con sus datos aislados del resto.
Excepciones
4Si el RUC de la empresa ya existe o los datos son inválidos: el sistema muestra un error y mantiene los datos para su corrección.

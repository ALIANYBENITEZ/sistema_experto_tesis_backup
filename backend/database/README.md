# Base de datos — PostgreSQL

Scripts de la base de datos del sistema, migrados de SQL Server 2022 a PostgreSQL.

## Archivos

| Archivo | Contenido |
|---|---|
| `01_schema.sql` | Referencia legible del esquema (tablas, PK, FK, UNIQUE, CHECK, índices). Idempotente. |
| `02_functions_triggers.sql` | Función helper + 4 triggers de auditoría a nivel BD (PL/pgSQL). |
| `03_views.sql` | Vistas de reportes/dashboard. |
| `04_seeds.sql` | Motor de reglas IF-THEN de ejemplo (10 reglas). Idempotente. |

> El esquema **canónico** lo genera `db.create_all()` desde los modelos SQLAlchemy
> al ejecutar `python seed.py`. `01_schema.sql` se mantiene como referencia y para
> instalaciones manuales sin Python.

## Instalar desde cero (local, Windows)

Requisitos: PostgreSQL 16+ instalado y corriendo en `localhost:5432`.

1. Crear rol y base (una sola vez), con el superusuario `postgres`:

   ```sql
   CREATE ROLE inmobiliaria WITH LOGIN PASSWORD 'inmobiliaria';
   CREATE DATABASE inmobiliaria_db OWNER inmobiliaria ENCODING 'UTF8';
   ```
   Y dentro de `inmobiliaria_db`:
   ```sql
   GRANT ALL ON SCHEMA public TO inmobiliaria;
   ALTER SCHEMA public OWNER TO inmobiliaria;
   ```

2. Configurar `backend/.env` (ver `backend/.env.example`):

   ```
   DATABASE_URL=postgresql+psycopg://inmobiliaria:inmobiliaria@localhost:5432/inmobiliaria_db
   ```

3. Instalar dependencias y crear tablas + admin + criterios:

   ```bash
   cd backend
   pip install -r requirements.txt
   python seed.py
   ```

4. Aplicar funciones/triggers, vistas y seeds del motor de reglas
   (usar la ruta a `psql.exe`, p. ej. `C:\Program Files\PostgreSQL\18\bin\psql.exe`):

   ```powershell
   $env:PGPASSWORD='inmobiliaria'
   $psql = "C:\Program Files\PostgreSQL\18\bin\psql.exe"
   & $psql -U inmobiliaria -h localhost -d inmobiliaria_db -f database\02_functions_triggers.sql
   & $psql -U inmobiliaria -h localhost -d inmobiliaria_db -f database\03_views.sql
   & $psql -U inmobiliaria -h localhost -d inmobiliaria_db -f database\04_seeds.sql
   ```

5. Arrancar el backend:

   ```bash
   python run.py
   ```

## Notas de migración

- `BIT` → `BOOLEAN`; `DATETIME2` → `TIMESTAMP` (sin zona, valores en UTC).
- `IDENTITY(1,1)` → `GENERATED BY DEFAULT AS IDENTITY`.
- `CONTEXT_INFO` → parámetro de sesión `app.origen` (la app hace `SET app.origen='APP'`).
- Los triggers de auditoría son `FOR EACH ROW`: registran una fila de auditoría por
  cada fila afectada en operaciones directas sobre la BD (fuera de la aplicación).
- Las búsquedas case-insensitive usan `ILIKE` (no dependen del collation).
